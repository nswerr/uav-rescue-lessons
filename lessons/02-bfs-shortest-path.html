BFS：找出步數最少的航線

有了格子地圖，下一步是讓程式自己找路。廣度優先搜尋（BFS）的想法很像丟一顆石頭進水裡：水波一圈一圈往外擴，最先碰到待查點的那一圈，就是最短的距離。

難度基礎
閱讀15 分鐘

學習目標

  • 能用自己的話說明 BFS 為什麼找到的是步數最少的路。
  • 能看懂 20 行以內的 Python BFS，並說出「回溯」在做什麼。
  • 能用同一張地圖驗證原路、改道、無路三種情況。

一　直覺：一圈一圈往外找

從起點 S 出發，先找出「走 1 步能到的格子」，再從這些格子找「走 2 步能到的格子」……每一圈都是距離起點相同步數的格子。因為是由近到遠搜尋，第一次碰到待查點 T 時，那一圈的步數就是最少步數，不可能有更短的路被漏掉。

要做到「由近到遠」，關鍵是一個佇列（queue）：先放進去的格子先拿出來處理，新發現的鄰居排到隊伍最後面。

二　演算法步驟

  1. 放入起點佇列只有 S，記錄 S 沒有前一格
  2. 取出最前面從佇列前端拿一格出來
  3. 檢查四個鄰居在地圖內、不是禁飛格、沒走過才加入
  4. 記錄來源寫下「這格是從哪一格來的」
  5. 到 T 就回溯沿來源一路倒推回 S，得到路徑

第 2～4 步會一直重複，直到拿出來的格子是 T（找到路），或佇列空了（沒有路）。

三　Python 實作

延續第 01 篇的 is_free()。prev 這個字典同時有兩個用途：記錄「走過了沒」以及「從哪裡來」。

from collections import deque

def find_path(start, goal):
    queue = deque([start])
    prev = {start: None}                  # 走過的格子 → 從哪一格來
    while queue:
        cur = queue.popleft()
        if cur == goal:                   # 第一次碰到 T：回溯
            path = []
            while cur is not None:
                path.append(cur)
                cur = prev[cur]
            return path[::-1]
        r, c = cur
        for nxt in [(r, c+1), (r+1, c), (r-1, c), (r, c-1)]:
            if is_free(nxt) and nxt not in prev:
                prev[nxt] = cur
                queue.append(nxt)
    return None                           # 佇列空了：無可行路徑

步數是路徑長度減 1，因為路徑同時包含起點和終點：len(path) - 1。

為什麼要有 nxt not in prev

沒有這個檢查，程式會在兩格之間來回跳，佇列永遠排不完。每一格只需要被發現一次，因為第一次發現時的步數就已經是最少的。

五　BFS 的適用範圍

BFS 保證最短，是建立在「每一步成本都一樣」的前提上。如果某些格子比較難飛（例如逆風區要算 3 步），一圈一圈的步數就不再等於成本，這時要改用 Dijkstra 演算法；若想利用「目標在右邊」這種方向資訊加快搜尋，則可以用 A*。

重點回顧

  • BFS 用佇列由近到遠搜尋，第一次碰到待查點時步數最少。
  • prev 字典同時記錄「走過沒」與「從哪來」，最後倒推出路徑。
  • 範例地圖：原路 7 步、封鎖第 4 列第 4 欄後 11 步、左右隔開則無路。
  • 每步成本不同時要改用 Dijkstra 或 A*。
